# 0001. Моделювання зв'язків M:N, сурогатних ключів та нормалізація моделі даних

## Контекст і постановка проблеми
При проектуванні концептуальної ER-моделі для онлайн-книгарні виникла необхідність визначити:
1. Спосіб відображення зв'язку «багато-до-багатьох» між виданнями (`Book`) та авторами (`Author`).
2. Потребу у виділенні агрегованого поля загальної вартості замовлення (`total_amount`).
3. Стратегію ідентифікації сутностей і зв'язків.

## Розглянуті варіанти
* **Варіант 1 (Фізична схема):** Впровадження проміжної зв'язкової таблиці `book_authors` без власних полів, збереження денормалізованого поля `total_amount` у сутності `Order`.
* **Варіант 2 (Концептуальна модель за 3NF):** Чистий M:N зв'язок без таблиць-пустушок, видалення `total_amount` для усунення надлишковості та використання єдиного типу `UUID` для всіх первинних/зовнішніх ключів.

## Результат рішення
Обрано **Варіант 2**.
* У концептуальній моделі відсутня потреба у сполучній таблиці без бізнес-атрибутів (`Book }|--o{ Author` відображає прямий зв'язок).
* Асоціативна сутність `OrderItem` виділена окремо, оскільки несе бізнес-атрибути (`quantity`, `unit_price`).
* Вилучення `total_amount` усуває похідну транзитивну залежність, забезпечуючи сувору відповідність 3-й нормальній формі (3NF).
